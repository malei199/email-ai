# V3 调度器路由规则（极简版）

> 版本：v2.0
> 更新日期：2026-05-01
> 核心变更：V3 退化为纯路由决策器，不做任何查询编排或结果判断

---

## 一、设计原则

1. **V3 只做一件事**：判断用户输入该走哪条路
2. **V3 不判断结果质量**：V1/V2 返回的内容直接输出，不做"够不够"的判断
3. **V3 不学查询策略**：V2 内部怎么查、查几次，V3 完全不知道
4. **V3 无状态**：不维护记忆、不分页、不处理续查

---

## 二、路由决策表（3 种输出）

| 用户输入特征 | V3 输出 |
|-----------|--------|
| **有款号（且单一意图）** | `{"decision": "route_v1", "style_id": "xxx"}` |
| **无款号** | `{"decision": "route_v2"}` |
| **问候 / 越界 / 模糊 / 多意图冲突** | `{"decision": "direct_answer", "answer": "..."}` |

**分析关键字不再触发特殊路由**："时间线"、"分析"、"进度"、"整体情况"、"汇总"、"风险"、"根因" 等关键字不改变路由决策——有款号走 V1，无款号走 V2。

---

## 三、三种路由的执行流程

### 3.1 `route_v1`（有款号）

```
用户: "CCSS230021 的时间线"
  ↓
V3: {"decision": "route_v1", "style_id": "CCSS230021"}
  ↓
【外部系统】
  1. 查 RAG/KG 获取该款式所有事件
  2. 排序、分轮
  3. 调 V1 模型生成 Markdown 报告
  4. 直接返回给用户（V3 不参与后续）
```

**V3 的职责到此结束**。外部系统负责：
- 事件查询、排序、分轮
- V1 模型调用（单轮或多轮）
- 结果合并、格式化
- 最终展示给用户

### 3.2 `route_v2`（无款号）

```
用户: "Iris Jiang 的款号进度怎么样"
  ↓
V3: {"decision": "route_v2"}
  ↓
【外部系统 / V2 引擎】
  1. V2 接收原始用户问题
  2. V2 内部自主决定查询策略（kg_query / rag_query / 多轮查询 / 分页）
  3. V2 返回最终结果
  4. 直接返回给用户（V3 不参与后续）
```

**V3 的职责到此结束**。V2 引擎负责：
- 解析用户意图
- 选择查询工具
- 多轮查询自治（如第一次 too_many，自动精确化再查）
- 分页截断（如款号过多，只返回前 N 个 + has_more 标记）
- 批量摘要生成（如返回款号列表，自动查摘要后汇总）
- 兜底处理（如查不到，返回友好提示）

### 3.3 `direct_answer`（问候 / 越界 / 模糊）

```
用户: "你好"
  ↓
V3: {"decision": "direct_answer", "answer": "你好！我是服装行业智能助手..."}
  ↓
直接返回给用户
```

## 四、V3 输出格式规范

### 4.1 `route_v1`

```json
{
  "decision": "route_v1",
  "style_id": "CCSS230021",
  "event": "延期"
}
```

- `style_id`：必填，提取到的款号
- `event`：可选，用户关注的事件类型（如"延期"、"样衣"）

### 4.2 `route_v2`

```json
{
  "decision": "route_v2"
}
```

**极简**。V3 不输出 function_calls、不指定查询参数。V2 引擎拿到原始用户问题自己处理。

### 4.3 `direct_answer`

```json
{
  "decision": "direct_answer",
  "answer": "你好！我是服装行业智能助手..."
}
```

---

## 五、越界定义

| 越界类型 | 示例 | V3 处理 |
|---------|------|--------|
| 问候 | "你好"、"在吗" | `direct_answer` |
| 非公司业务 | "讲个笑话"、"今天天气" | `direct_answer` |
| 多意图冲突 | "CCSS230021 的信息，我的订单都什么情况" | `direct_answer`，提示拆分 |
| 模糊提问 | "怎么样"、"查一下"（无款号无主体） | `direct_answer`，引导提供款号 |
| 无效款号格式 | "ABCDEFG" | `route_v1`（V3 不验证款号有效性，交给 V1/V2） |

## 六、外部系统职责（V3 之外）

### 6.1 输入预处理（V3 之前）

| 功能 | 说明 |
|-----|------|
| 指代消解 | "这个款号怎么样了" → 结合上下文补全款号 |
| 问题改写 | 续查"剩下的呢" → 外部系统查记忆直接返回，**绕过 V3** |
| 多意图检测 | 检测有款号+无款号混合 → 直接返回提示，**不经过 V3** |

### 6.2 V1 链路（V3 之后）

| 环节 | 负责方 |
|-----|--------|
| 事件查询 | 外部框架调 RAG/KG API |
| 排序 | 外部框架按 date 排序 |
| 分轮 | 外部框架按 token 上限切分 |
| 调 V1 | 外部框架串行/并行调用 |
| 合并结果 | 外部框架拼接多轮 Markdown |
| 返回用户 | 外部框架直接展示 |

### 6.3 V2 链路（V3 之后）

| 环节 | 负责方 |
|-----|--------|
| 意图解析 | V2 引擎内部 |
| 工具选择 | V2 引擎内部（kg_query / rag_query / email_extract） |
| 多轮查询 | V2 引擎内部自治 |
| 分页截断 | V2 引擎内部（最多返回 N 个款号） |
| 批量摘要 | V2 引擎内部（款号列表 → 自动查摘要 → 汇总） |
| 兜底处理 | V2 引擎内部（查不到时返回友好提示） |
| 返回用户 | V2 引擎直接展示 |

### 6.4 记忆系统（外部维护）

| 场景 | 处理 |
|-----|------|
| 用户问"剩下的呢" | 外部系统查 Redis/DB 记忆 → 直接返回下一页 → **绕过 V3** |
| 用户问"第3个款号详细点" | 外部系统查记忆定位第3个 → 调 V1 分析 → **绕过 V3** |
| 会话上下文 | 外部系统维护，V3 无感知 |

## 七、与旧规则的变更点

| 旧规则（v1.x） | 新规则（v2.0） |
|--------------|--------------|
| 4 种路由（+ `route_v2_then_v1`） | **3 种路由**，删除 `route_v2_then_v1` |
| V3 判断 V2 结果"够不够用" | **V3 不做判断**，V2 自治返回完整结果 |
| V3 输出 `function_calls` 指定查什么 | **V3 只输出 `route_v2`**，V2 自己决定查什么 |
| V3 参与多轮查询编排 | **V3 只参与 1 轮**（初始路由），后续 V2 自治 |
| 分析关键字触发 `route_v2_then_v1` | **分析关键字不影响路由**，有款号走 V1，无款号走 V2 |
| V3 训练数据 3-5 轮 | **V3 训练数据 1 轮**（只有初始决策） |
| V3 需要学模板选择（模板一~五） | **V3 不学模板**，模板选择由外部系统/V2 负责 |

## 八、训练数据规格

### 8.1 单条样本结构（1 轮决策）

```json
{
  "scene": "route_v1",
  "messages": [
    {"role": "system", "content": "你是服装行业智能调度器。根据用户问题，决定如何回答：\n1. direct_answer: 直接回答（问候、超出范围、模糊提问等）\n2. route_v2: 调用 V2 查询引擎（无款号）\n3. route_v1: 调用 V1 时间线推理模型（有款号）\n输出格式：{\"decision\": \"...\", ...}"},
    {"role": "user", "content": "CCSS230021 的时间线"},
    {"role": "assistant", "content": "{\"decision\": \"route_v1\", \"style_id\": \"CCSS230021\"}"}
  ]
}
```

```json
{
  "scene": "route_v2",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "Iris Jiang 的款号进度怎么样"},
    {"role": "assistant", "content": "{\"decision\": \"route_v2\"}"}
  ]
}
```

```json
{
  "scene": "direct_answer",
  "messages": [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "{\"decision\": \"direct_answer\", \"answer\": \"你好！我是服装行业智能助手...\"}"}
  ]
}
```

### 8.2 场景分布

| 场景 | 比例 | 说明 |
|-----|------|------|
| `route_v1` | ~40% | 有款号，核心场景 |
| `route_v2` | ~43% | 无款号 |
| `direct_answer` | ~12% | 问候、能力说明 |
| `boundary` | ~5% | 越界、模糊、多意图冲突 |

### 8.3 DPO 错误模式

| 正确决策 | 错误决策（rejected） |
|---------|-------------------|
| `route_v1`（有款号） | `route_v2`（有款号却走 V2） |
| `route_v2`（无款号） | `direct_answer`（无款号却拒绝服务） |
| `route_v2`（无款号） | `route_v1`（无款号却走 V1，V1 无输入） |
| `direct_answer`（问候） | `route_v2`（问候却走 V2） |

## 九、完整示例

### 示例 1：`route_v1`

```
用户: "CCSS230021 为什么延期了？"

V3 输出: {"decision": "route_v1", "style_id": "CCSS230021", "event": "延期"}

外部系统:
  1. 查 RAG → 获取 CCSS230021 的所有事件
  2. 排序、分轮
  3. 调 V1 → 生成 Markdown 分析报告
  4. 直接展示给用户

用户看到:
  ## 📋 款号 CCSS230021 时间线分析
  ...
```

### 示例 2：`route_v2`（直接查询）

```
用户: "taffeta 怎么翻译"

V3 输出: {"decision": "route_v2"}

V2 引擎内部:
  1. 解析意图 → 术语翻译
  2. 查 RAG/词典 → "taffeta = 塔夫绸"
  3. 直接返回结果

用户看到:
  taffeta 译为：塔夫绸
```

### 示例 3：`route_v2`（批量摘要）

```
用户: "我跟的款号有哪些"

V3 输出: {"decision": "route_v2"}

V2 引擎内部:
  1. 解析意图 → 查询我的款号
  2. kg_query("我的款号") → 返回 15 个款号
  3. 截断前 5 个 → 批量查摘要
  4. 汇总返回

用户看到:
  共查询到 5 个款号（还有 10 个）：

  ⚠️ 延期 (1个)：
    • 9252723 - 出货 - 延期1天

  ✅ 正常 (4个)：
    • CCSS240138 - 核料
    • ...
```

### 示例 4：续查（绕过 V3）

```
用户: "剩下的呢"

外部系统:
  1. 查记忆 → 上次返回了第 1 页（5/15）
  2. 直接返回第 2 页（6-10/15）
  3. 无需经过 V3

用户看到:
  第 2 页（6-10/15）：
    • CCSS240139 - 样衣 - 正常
    • ...
```

### 示例 5：`direct_answer`

```
用户: "你好"

V3 输出: {"decision": "direct_answer", "answer": "你好！我是服装行业智能助手..."}

用户看到:
  你好！我是服装行业智能助手...
```
